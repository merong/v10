The markup

<link rel="stylesheet" href="/video-ads.css" />
<script defer src="/video-ads.iife.js"></script>

<video-player>
  <video-skin>
    <video src="/video.mp4" playsinline></video>
    <media-ads src="/ads.json"></media-ads>
  </video-skin>
</video-player>

That is the whole integration. <media-ads> finds the player through context, fetches the ad list, waits for the viewer's first play, runs the ad, and hands playback back.

It draws nothing where it sits, so its position among the skin's children does not matter. It adds nothing to the player store either, which is what lets it drop into any v10 player rather than one built with an ads feature.

Which file to load

File Carries Load with
video-ads.iife.js Player and ads <script defer>
video-ads.js Player and ads <script type="module">
videojs-ads.js Ads only <script type="module">, next to a player you already load

Each is one file — no chunks to host alongside it. Pair any of them with video-ads.css, which carries the overlay's styles.

defer is required on the classic script, not decoration. A classic script runs while the parser is still working, so without it <video-player> upgrades before its <video> child exists and never finds media to attach to — the controls render but stay inert. A module script is deferred already. Putting the script at the end of <body> works too.

Ad data

src points at JSON shaped like this:

{
  "ads": [
    {
      "id": "video-preroll",
      "type": "video",
      "src": "/media/ad.mp4",
      "mime": "video/mp4",
      "duration": 10,
      "skipAfter": 3,
      "clickUrl": "https://example.com",
      "trackingUrl": "/api/ad-events"
    }
  ]
}

The first entry in the list runs.

Field Required Meaning
idyesYour identifier; reported with tracking events.
typeyesvideo or image.
srcyesThe ad's media URL.
mimeyesContent type of that media.
durationyesSeconds the ad runs.
skipAfteryesSeconds until the skip button becomes usable. 0 makes it skippable immediately.
clickUrlnoOpened in a new tab when the ad is clicked.
trackingUrlnoEndpoint for the beacons below. Omit it and no beacons fire.
Format type Rendered as
MP4, WebMvideo<video>, autoplaying
WebP, GIFimage<img>, held for duration

A malformed entry is dropped, and a failed request yields an empty list — either way the content plays as if no ad were scheduled. An ad server outage never costs you playback.

Attributes

Attribute Default Effect
src—Where to fetch the ad list. Without it the element does nothing.
skip-labelSkip adButton text once skipping is allowed.
skip-countdown-labelSkip in {seconds}sButton text before then.
timer-labelAD {elapsed} / {duration}Bottom-left readout.
media-altAdvertisementalt on an image ad.
tick-interval250Countdown refresh rate, in milliseconds.
max-wait5Extra wall-clock seconds allowed past duration before the ad is abandoned.
 
<media-ads
  src="/ads.json"
  skip-label="광고 건너뛰기"
  skip-countdown-label="{seconds}초 후 건너뛰기"
  timer-label="광고 {elapsed} / {duration}"
></media-ads>

An attribute cannot carry a function, so the countdown and timer take templates. {seconds}, {elapsed}, and {duration} mark where the numbers go, and the number does not sit in the same place in every language — which is why these are templates rather than a prefix and a suffix.

These labels do not go through the player's translation registry. The overlay is constructed directly rather than resolved from the player's locale, so you pass the strings you want.

Styling the overlay

The overlay lives in light DOM, so your own stylesheet reaches it — load yours after video-ads.css and override.

Class Element
.vjs-ads-overlayRoot, covering the player at z-index: 100
.vjs-ads-mediaThe ad's video or image, object-fit: contain
.vjs-ads-timerBottom-left readout
.vjs-ads-skipBottom-right button

State is on data attributes, so styling follows it without a class toggle:

Selector When
.vjs-ads-overlay[data-ad-phase="playing"]An ad is showing
.vjs-ads-overlay[data-ad-phase="hidden"]No ad
.vjs-ads-skip[data-skip-available="true"]Skip is usable
.vjs-ads-skip[data-skip-available="false"]Still counting down
 
.vjs-ads-skip {
  background: rgb(255 200 0 / 0.9);
  color: #000;
  border: none;
  border-radius: 8px;
}

.vjs-ads-skip[data-skip-available="true"]:hover {
  background: rgb(255 220 50);
}

Tracking

With a trackingUrl on the ad, the overlay POSTs a small JSON body at each of these moments. Without one, nothing is sent.

Event Fired when
impressionThe ad starts
clickThe viewer clicks the ad
skipThe viewer skips
completeThe ad reaches its duration
errorThe ad's media failed to load or play

Beacons use keepalive, so a click that navigates away still reports.

Driving it yourself

When the element's lifecycle is not what you want — a midroll, an ad chosen per viewer, your own scheduling — the same bundles export the pieces it is built from.

Export Role
fetchAds(url, signal?)Reads a list and drops malformed entries. Resolves to [] on failure.
AdsOverlayDraws the ad: media, timer, skip button.
trackAdEvent(url, event)Fires one beacon.
 
import { AdsOverlay, fetchAds } from '/video-ads.js';

const overlay = new AdsOverlay(container, {
  labels: { skipCountdown: (seconds) => `${seconds}초 후 건너뛰기` },
});

Constructing it yourself takes the labels as functions rather than templates. The container you pass must establish a positioning context, which the element normally arranges for you.

Troubleshooting

Controls render but nothing responds

The player never attached to media. On a classic script this is the missing defer described above. Confirm with document.querySelector('video-player').store.target — it is null when unattached.

No ad, but the content plays

By design. Check the network tab for the src request: a failed fetch, invalid JSON, or an entry missing a required field all reduce to an empty list, and an empty list means no ad.

The overlay is behind something

It sits at z-index: 100 within the skin. Look for a larger z-index on your own overlay elements rather than on the player.

An ad outlasts its duration

In a background tab the browser throttles the wall-clock timer that backs the countdown, so an ad with no playback progress of its own finishes late. A playing video ad is unaffected. tick-interval does not help here — the throttle applies whatever the interval asks for.

The ad never ends

It should not be possible: the wall clock ends the ad at duration plus max-wait even when the ad's media reports nothing, and a media error ends it at once. If you see it, check that the page is loading a build that includes both — earlier builds drove the countdown from timeupdate alone and an unreachable ad URL would hold the content indefinitely.
