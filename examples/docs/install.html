무엇을 설치하나

어떤 방식을 고르든 페이지가 불러오는 것은 JavaScript 파일 하나와 CSS 파일 하나입니다. 빌드 도구도, 초기화 코드도 필요하지 않습니다. 스크립트가 커스텀 엘리먼트를 등록하고 나면 나머지는 마크업이 합니다. 

<link rel="stylesheet" href="/video-ads.css" />
<script defer src="/video-ads.iife.js"></script>

<video-player>
  <video-skin>
    <video src="/video.mp4" playsinline></video>
    <media-ads src="/ads.json"></media-ads>
  </video-skin>
</video-player>

CSS 파일이 하나뿐인 이유가 있습니다. 스킨의 스타일은 shadow root 안에 적용되는데, 링크된 스타일시트는 shadow 경계를 넘지 못하므로 플레이어 번들이 직접 들고 있다가 런타임에 적용합니다. 여러분이 링크할 video-ads.css는 light DOM에 있는 것 — 광고 오버레이 — 만 담습니다.

파일 만들기

@videojs/ads는 npm에 배포되지 않은 이 포크 전용 패키지입니다. 따라서 파일은 저장소에서 직접 빌드합니다. 

pnpm install
pnpm -F @videojs/ads build:cdn

결과물은 packages/ads/cdn/에 생성되고, 예제가 바로 쓸 수 있도록 examples/ads/dist/로도 복사됩니다. 이 디렉터리들은 빌드 산출물이라 저장소에 커밋되지 않으므로, 새로 클론했다면 위 명령을 먼저 실행해야 합니다.

파일 크기 gzip 용도
video-ads.iife.js415 KB110 KB플레이어 + 광고, 클래식 스크립트용
video-ads.js415 KB110 KB플레이어 + 광고, 모듈용
videojs-ads.js10 KB3 KB광고만, 이미 있는 플레이어 옆에
video-ads.css2 KB1 KB광고 오버레이 스타일. 세 방식 공통
*.dev.js——압축하지 않은 디버깅용 빌드. 배포용은 아닙니다

세 번들 모두 import가 하나도 없는 완결된 단일 파일입니다. 옆에 함께 올려야 할 청크나 로케일 조각이 없으므로, 파일을 복사해 정적 경로에 두는 것으로 배포가 끝납니다.

어떤 방식을 고를까

방식 호스팅할 파일 이럴 때 고르세요
IIFE video-ads.iife.js + video-ads.css type="module"을 쓸 수 없는 페이지. 레거시 템플릿, CMS, 스크립트 태그만 끼워 넣을 수 있는 환경
ESM video-ads.js + video-ads.css 모듈을 쓸 수 있는 보통의 페이지. 기본으로 권합니다
CDN videojs-ads.js + video-ads.css (10 KB + 2 KB) 플레이어를 직접 호스팅하고 싶지 않을 때. 또는 이미 @videojs/html을 불러오고 있어 광고만 얹으면 될 때

IIFE — 클래식 스크립트

  1. video-ads.iife.js와 video-ads.css를 정적 파일 경로에 복사합니다.
  2. <head>에 스타일시트와 스크립트를 넣습니다. defer를 반드시 붙입니다.
  3. 마크업을 작성합니다.
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <link rel="stylesheet" href="/assets/video-ads.css" />
    <script defer src="/assets/video-ads.iife.js"></script>
    <style>
      video-skin { display: block; width: 100%; aspect-ratio: 16 / 9; }
    </style>
  </head>
  <body>
    <video-player>
      <video-skin>
        <video src="/media/video.mp4" playsinline></video>
        <media-ads src="/ads.json"></media-ads>
      </video-skin>
    </video-player>
  </body>
</html>

defer는 필수입니다. 클래식 스크립트는 파서가 아직 문서를 읽는 중에 실행되므로, defer가 없으면 <video-player>가 자식 <video>가 생기기 전에 업그레이드되어 붙을 미디어를 찾지 못합니다. 컨트롤은 그려지지만 아무것도 반응하지 않습니다. 스크립트를 </body> 직전에 두어도 같은 효과를 냅니다.

전역으로 VideojsAds가 노출됩니다. 광고를 직접 제어할 때만 쓰면 되고, 보통은 건드릴 일이 없습니다.

ESM — 모듈 스크립트

  1. video-ads.js와 video-ads.css를 정적 파일 경로에 복사합니다.
  2. <script type="module">로 불러옵니다. 모듈은 이미 defer 상태라 defer가 필요 없습니다.
<link rel="stylesheet" href="/assets/video-ads.css" />
<script type="module" src="/assets/video-ads.js"></script>

<video-player>
  <video-skin>
    <video src="/media/video.mp4" playsinline></video>
    <media-ads src="/ads.json"></media-ads>
  </video-skin>
</video-player>

번들러를 쓰는 프로젝트라면 같은 파일을 import '/assets/video-ads.js'처럼 진입점에서 한 번 불러오면 됩니다. 이 파일은 부수 효과로 엘리먼트를 등록하므로 이름을 가져올 필요가 없습니다.

CDN — 플레이어는 CDN, 광고는 로컬

플레이어(@videojs/html)는 npm에 배포되어 있어 jsDelivr에서 바로 받을 수 있습니다. 배포되지 않은 것은 광고 코드뿐이므로, 이 방식에서 여러분이 호스팅할 파일은 10 KB짜리 videojs-ads.js와 2 KB짜리 CSS가 전부입니다. 

<link rel="stylesheet" href="/assets/video-ads.css" />

<!-- 플레이어가 먼저, 광고가 나중입니다. -->
<script
  type="module"
  src="https://cdn.jsdelivr.net/npm/@videojs/html@10.0.0-beta.26/cdn/video.js"
></script>
<script type="module" src="/assets/videojs-ads.js"></script>

<video-player>
  <video-skin>
    <video src="/media/video.mp4" playsinline></video>
    <media-ads src="/ads.json"></media-ads>
  </video-skin>
</video-player>

스크립트 순서를 지키세요. 광고 스크립트를 플레이어보다 먼저 두면 광고가 실행되지 않습니다. <media-ads>가 먼저 업그레이드되어 아직 존재하지 않는 플레이어에게 컨텍스트를 요청하고, 뒤늦게 나타난 플레이어는 그 요청을 다시 받아주지 않기 때문입니다. 광고 목록은 정상적으로 내려받아지므로 네트워크 탭만 봐서는 원인이 드러나지 않습니다.

버전은 고정하는 편이 안전합니다. 위 URL의 @10.0.0-beta.26을 빼면 jsDelivr가 언제나 최신 버전을 내려주고, 플레이어가 예고 없이 바뀝니다. 이 문서를 쓰는 시점의 최신 버전이 10.0.0-beta.26이며, 이 저장소의 플레이어도 같은 버전입니다.

플레이어 번들의 선택지는 video.js 하나가 아닙니다. 스킨과 기능 구성이 다른 video-minimal.js, 스킨이 없는 video-headless.js, 오디오용 번들이 각각 있습니다 — 플레이어 설정과 제어의 번들 선택 항목을 참고하세요.

설치 확인

페이지를 열고 콘솔에서 세 가지를 확인하면 설치가 끝났는지 알 수 있습니다.

// 1. 두 엘리먼트가 등록되었는가
customElements.get('video-player');   // class …
customElements.get('media-ads');      // class …

// 2. 플레이어가 미디어에 붙었는가 (null이면 defer 누락을 의심)
document.querySelector('video-player').store.target;

// 3. 광고 목록을 받아왔는가
//    네트워크 탭에서 ads.json 요청이 200인지 확인

마지막은 눈으로 확인하는 편이 빠릅니다. 재생을 누르면 본편 대신 광고가 먼저 재생되고, 좌측 하단에 AD 0:01 / 0:10, 우측 하단에 건너뛰기 버튼이 보이면 정상입니다.

문제 해결

페이지가 비어 있고 콘솔에 404가 보입니다

dist/가 아직 없는 경우입니다. 빌드 산출물은 커밋되지 않으므로 pnpm -F @videojs/ads build:cdn을 먼저 실행하세요.

컨트롤은 보이는데 아무것도 반응하지 않습니다

클래식 스크립트에서 defer를 빠뜨린 경우입니다. document.querySelector('video-player').store.target이 null이면 이 문제입니다.

플레이어는 뜨는데 광고만 실행되지 않습니다

CDN 방식이라면 스크립트 순서를 확인하세요 — 플레이어가 먼저여야 합니다. 순서가 맞다면 광고 데이터 쪽입니다. 요청 실패, 잘못된 JSON, 필수 필드가 빠진 항목은 모두 빈 목록이 되고, 빈 목록은 광고 없음을 뜻합니다. 광고 데이터에서 필수 필드를 확인하세요.

HTML 파일을 더블클릭해서 열었더니 아무것도 뜨지 않습니다

file://로 연 페이지에서는 브라우저가 모듈 스크립트 로드와 fetch를 막습니다. 광고 목록도 같은 이유로 받아올 수 없습니다. 로컬에서 볼 때도 HTTP로 서빙하세요. 

cd examples
python3 -m http.server 5192

플레이어 영역이 납작하게 보입니다

<video-skin>은 컨테이너를 채우므로 높이가 없는 컨테이너 안에서는 무너집니다. display: block과 aspect-ratio를 주세요.

위의 파일 크기와 동작은 이 저장소의 빌드를 브라우저에서 직접 확인한 값입니다.
