Configure and control the player

What you can set on a Video.js 10 player from plain HTML, and what you can call on it from a script.

Two halves

There is no init call and no options object. The player is a set of custom elements, so loading the script registers them and the markup does the rest. Configuration and control are separate:

  • Configuration is markup. Attributes and slots, set before or while the player runs.
  • Control is script. Every player element exposes a store holding current state and the actions that change it.

A page that only needs a player to appear never touches the second half. See the ad examples for three ways to load the script itself.

What you configure

Configuration lives in four places, and which one you use depends on what you are setting.

The media element

Playback options are the standard HTML media attributes, on the <video> or <audio> element (or a media element like <hlsjs-video>). Nothing here is Video.js-specific. 

<video-player>
  <video-skin>
    <video
      src="/video.mp4"
      poster="/poster.jpg"
      preload="metadata"
      crossorigin="anonymous"
      playsinline
      muted
      loop
    ></video>
  </video-skin>
</video-player>
Attribute Effect
srcWhat to play.
autoplayStart without a gesture. Browsers only allow it when also muted.
mutedStart silent.
loopRestart on end.
playsinlinePlay in place on iOS instead of going fullscreen.
preloadnone, metadata, or auto.
crossoriginNeeded for text tracks and thumbnails from another origin.
posterStill shown before playback.

The player element

<video-player> takes configuration that belongs to the player rather than to the media. Each player feature can declare configuration keys, which become kebab-cased attributes. In the standard video preset that is metadata:

Attribute Reads back as Effect
content-title store.contentTitle Title shown by the UI. Wins over a title the media itself reports.
default-content-title store.contentTitle Fallback used only when neither of the other two is set. 
<video-player content-title="Big Buck Bunny">

These are live. Setting the attribute later — player.setAttribute('content-title', 'Episode 2') — flows through to store.contentTitle.

Slots and child elements

Some things are elements rather than attributes:

Markup Purpose
<img slot="poster"> Poster you want the skin to render and manage, rather than the browser's own.
<track kind="chapters"> Chapter markers on the time slider.
<track kind="metadata"> Storyboard thumbnails shown while scrubbing.
<media-i18n> Wraps the player to translate control labels. Not needed for English.

The bundle you load

The largest configuration decision is made before any markup: which script you load. It fixes the skin and which features the store has. video.js and video-minimal.js give different skins; video-headless.js gives none. An audio bundle builds a store without fullscreen or picture-in-picture because an audio player has no use for them.

Getting the store

Every player element exposes its store as a property:

const player = document.querySelector('video-player');
const store = player.store;

It is ready as soon as your script runs, provided the player script ran first. In a module script that is automatic, since modules are deferred and execute in order.

State is not. store.target is populated immediately, but anything the media reports — duration, canPlay, track lists — stays empty until metadata loads. Reading duration in the same tick gives 0. Subscribe instead of reading once.

Reading, calling, subscribing

State and actions sit directly on the store. There is no getState() and no dispatch.

store.paused;        // true
store.currentTime;   // 0
store.duration;      // 25.32 once metadata has loaded

store.play();
store.seek(30);
store.setVolume(0.5);
store.toggleFullscreen();

subscribe tells you something changed and returns a function that stops it:

const stop = store.subscribe(() => {
  progress.value = store.currentTime / store.duration;
});

// later
stop();

The callback takes no arguments. It is a notification, not a payload — read the values you care about off the store inside it.

The full surface

What follows is the store of a standard video player. An audio or background player has fewer groups. Rather than trusting this table, you can always print the real one: 

const store = document.querySelector('video-player').store;
console.log(Object.keys(store));
Group State Actions
Playback paused, ended, started, waiting play(), pause(), togglePaused()
Time currentTime, duration, seeking seek(time)
Volume volume, muted, volumeAvailability, mutedAvailability setVolume(level), toggleMuted()
Playback rate playbackRate, playbackRates setPlaybackRate(rate)
Source source, canPlay loadSource(source)
Buffer buffered, seekable —
Quality videoRenditionList, activeVideoRendition selectVideoRendition(rendition)
Audio tracks audioTrackList selectAudioTrack(track)
Text tracks textTrackList, subtitlesShowing, chaptersCues, thumbnailCues, thumbnailTrackSrc toggleSubtitles(on), selectSubtitlesTrack(track)
Fullscreen fullscreen, fullscreenAvailability requestFullscreen(), exitFullscreen(), toggleFullscreen()
Picture-in-picture pip, pipAvailability requestPictureInPicture(), exitPictureInPicture(), togglePictureInPicture()

Metadata contentTitle setContentTitle(title), setDefaultContentTitle(title)

Alongside those the store carries its own lifecycle: target (the media and container it is attached to), destroyed, subscribe(), attach(), and destroy(). The player element manages attach and destroy for you; you rarely call them yourself.

An *Availability value tells you whether the browser offers that capability at all — check it before showing a control for it.

Gotchas

Writes land on the next microtask

Reading straight back gives you the old value:

store.setVolume(0.5);
store.volume;                       // still 1

queueMicrotask(() => store.volume); // 0.5

Several actions in one tick collapse into a single subscribe callback, which is what you want for rendering — but it means you cannot treat an action as synchronous.

Media state starts empty

duration is 0 and canPlay is false until the browser has the metadata. Track lists are empty for the same reason. Anything reading these should go through subscribe.

The skin needs a size

<video-skin> fills its container, and a container with no height collapses to nothing. Give it one: 

video-skin {
  display: block;
  width: 100%;
  aspect-ratio: 16 / 9;
}

The tables above were read off a running player rather than transcribed, so they describe the build in this repository. Print Object.keys(store) to check yours.
