플레이어 설정과 제어

Video.js 10 플레이어를 순수 HTML로 설정하는 방법과, 스크립트에서 호출할 수 있는 것들.

페이지에 올리는 절차는 설치 가이드, 광고는 프리롤 광고 실행하기에 있습니다.

두 갈래

초기화 함수도, 옵션 객체도 없습니다. 플레이어는 커스텀 엘리먼트의 묶음이라서, 스크립트를 불러오면 엘리먼트가 등록되고 나머지는 마크업이 합니다. 설정과 제어는 서로 분리되어 있습니다.

  • 설정은 마크업입니다. 속성과 슬롯으로, 플레이어가 뜨기 전에도 도중에도 지정합니다.
  • 제어는 스크립트입니다. 모든 플레이어 엘리먼트는 현재 상태와 그것을 바꾸는 액션을 담은 store를 노출합니다.

플레이어를 화면에 띄우기만 하면 되는 페이지는 두 번째 갈래를 건드릴 일이 없습니다. 스크립트를 불러오는 세 가지 방식은 광고 예제에서 확인하세요.

무엇을 설정하나

설정이 들어가는 자리는 네 군데이고, 무엇을 설정하느냐에 따라 자리가 정해집니다.

미디어 엘리먼트

재생 옵션은 <video>나 <audio> 엘리먼트(또는 <hlsjs-video> 같은 미디어 엘리먼트)에 붙이는 표준 HTML 미디어 속성입니다. 여기에 Video.js 고유의 것은 없습니다. 

<video-player>
  <video-skin>
    <video
      src="/video.mp4"
      poster="/poster.jpg"
      preload="metadata"
      crossorigin="anonymous"
      playsinline
      muted
      loop
    ></video>
  </video-skin>
</video-player>
속성 효과
src재생할 대상.
autoplay사용자 조작 없이 시작. 브라우저는 muted가 함께 있을 때만 허용합니다.
muted무음으로 시작.
loop끝나면 다시 재생.
playsinlineiOS에서 전체화면으로 넘어가지 않고 제자리에서 재생.
preloadnone, metadata, auto 중 하나.
crossorigin다른 출처의 텍스트 트랙과 썸네일을 쓰려면 필요합니다.
poster재생 전에 보여줄 정지 이미지.

플레이어 엘리먼트

<video-player>는 미디어가 아니라 플레이어에 속하는 설정을 받습니다. 각 플레이어 기능이 설정 키를 선언할 수 있고, 그 키가 케밥 케이스 속성이 됩니다. 표준 video 프리셋에서는 메타데이터가 그렇습니다.

속성 읽을 때 효과
content-title store.contentTitle UI에 표시되는 제목. 미디어가 보고하는 제목보다 우선합니다.
default-content-title store.contentTitle 앞의 둘 중 어느 것도 없을 때만 쓰이는 대체값. 
<video-player content-title="Big Buck Bunny">

이 속성들은 살아 있습니다. 나중에 속성을 바꿔도 — player.setAttribute('content-title', 'Episode 2') — store.contentTitle까지 반영됩니다.

슬롯과 자식 엘리먼트

속성이 아니라 엘리먼트로 주는 것들도 있습니다.

마크업 용도
<img slot="poster"> 브라우저 기본 포스터 대신, 스킨이 직접 그리고 관리할 포스터.
<track kind="chapters"> 타임 슬라이더 위의 챕터 표시.
<track kind="metadata" label="thumbnails"> 탐색 중 표시되는 스토리보드 썸네일. 이것을 식별하는 것은 라벨입니다 — 라벨이 다른 metadata 트랙은 무시됩니다.
<media-i18n> 플레이어를 감싸 컨트롤 라벨을 번역합니다. 영어만 쓴다면 필요 없습니다.
<media-ads> 본편 앞에 프리롤을 실행합니다. 프리롤 광고 실행하기 참고.

어떤 번들을 불러오는가

가장 큰 설정은 마크업을 쓰기 전에 결정됩니다. 어떤 스크립트를 불러오느냐가 스킨과 스토어가 갖는 기능을 고정합니다. video.js와 video-minimal.js는 서로 다른 스킨을 주고, video-headless.js는 스킨을 주지 않습니다. audio 번들은 전체화면과 PiP 없이 스토어를 구성합니다 — 오디오 플레이어에는 쓸 일이 없기 때문입니다.

번들을 페이지에 올리는 방법은 세 가지(IIFE, ESM, CDN)이고, 각각의 절차와 조건은 설치 가이드에 있습니다.

스토어 가져오기

모든 플레이어 엘리먼트는 스토어를 프로퍼티로 노출합니다.

const player = document.querySelector('video-player');
const store = player.store;

플레이어 스크립트가 먼저 실행되었다면, 여러분의 스크립트가 도는 시점에 스토어는 이미 준비되어 있습니다. 모듈 스크립트라면 자동으로 그렇게 됩니다 — 모듈은 defer 되고 순서대로 실행되기 때문입니다.

클래식 스크립트에는 defer가 필요합니다. 없으면 파서가 아직 문서를 읽는 중에 스크립트가 실행되어, <video-player>가 자식 <video>가 생기기 전에 업그레이드되고 끝내 미디어에 붙지 못합니다. 스토어도 있고 컨트롤도 그려지지만 store.target은 null이고 아무것도 반응하지 않습니다.

상태는 준비되어 있지 않습니다. store.target은 즉시 채워지지만, 미디어가 보고하는 값 — duration, canPlay, 트랙 목록 — 은 메타데이터가 로드될 때까지 비어 있습니다. 같은 tick에서 duration을 읽으면 0입니다. 한 번 읽지 말고 구독하세요.

읽기, 호출하기, 구독하기

상태와 액션은 스토어에 바로 놓여 있습니다. getState()도 dispatch도 없습니다.

store.paused;        // true
store.currentTime;   // 0
store.duration;      // 25.32 (메타데이터 로드 후)

store.play();
store.seek(30);
store.setVolume(0.5);
store.toggleFullscreen();

subscribe는 무언가 바뀌었음을 알려주고, 구독을 멈추는 함수를 돌려줍니다.

const stop = store.subscribe(() => {
  progress.value = store.currentTime / store.duration;
});

// 나중에
stop();

콜백은 인자를 받지 않습니다. 값이 실려 오는 게 아니라 알림일 뿐이니, 필요한 값은 콜백 안에서 스토어에서 직접 읽으세요.

전체 목록

아래는 표준 video 플레이어의 스토어입니다. audio나 background 플레이어는 그룹이 더 적습니다. 이 표를 믿는 대신, 언제든 실제 목록을 출력해 볼 수 있습니다. 

const store = document.querySelector('video-player').store;
console.log(Object.keys(store));
그룹 상태 액션
재생 paused, ended, started, waiting play(), pause(), togglePaused()
시간 currentTime, duration, seeking seek(time)
볼륨 volume, muted, volumeAvailability, mutedAvailability setVolume(level), toggleMuted()
재생 속도 playbackRate, playbackRates setPlaybackRate(rate)
소스 source, canPlay loadSource(source)
버퍼 buffered, seekable —
화질 videoRenditionList, activeVideoRendition selectVideoRendition(rendition)
오디오 트랙 audioTrackList selectAudioTrack(track)
텍스트 트랙 textTrackList, subtitlesShowing, chaptersCues, thumbnailCues, thumbnailTrackSrc toggleSubtitles(on), selectSubtitlesTrack(track)
전체화면 fullscreen, fullscreenAvailability requestFullscreen(), exitFullscreen(), toggleFullscreen()
PiP pip, pipAvailability requestPictureInPicture(), exitPictureInPicture(), togglePictureInPicture()
원격 재생 remotePlaybackState, remotePlaybackAvailability toggleRemotePlayback()
컨트롤 userActive, controlsVisible requestControlsLock(), toggleControls()

메타데이터 contentTitle setContentTitle(title), setDefaultContentTitle(title)

이 밖에 스토어는 자신의 생명주기도 함께 갖습니다: target(붙어 있는 미디어와 컨테이너), destroyed, subscribe(), attach(), destroy(). attach와 destroy는 플레이어 엘리먼트가 알아서 처리하므로 직접 부를 일은 거의 없습니다.

*Availability 값은 브라우저가 그 기능을 제공하는지 자체를 알려줍니다 — 해당 컨트롤을 노출하기 전에 확인하세요.

함정

쓴 값이 곧바로 읽히지는 않습니다

스토어가 직접 소유한 상태는 즉시 갱신됩니다. 반면 미디어가 소유한 것 — volume, muted — 은 미디어 엘리먼트에 설정되고, 브라우저가 되돌려 보고할 때 비로소 스토어에 도달합니다. 한 턴 이상 뒤의 일입니다. 

store.setContentTitle('Episode 2');
store.contentTitle;                  // 'Episode 2', 즉시

store.setVolume(0.5);
store.volume;                        // 여전히 1
queueMicrotask(() => store.volume);  // 여전히 1 — 마이크로태스크로는 부족합니다
setTimeout(() => store.volume);      // 0.5

어느 쪽인지 외우는 대신, 어떤 액션도 동기적이라고 보지 말고 subscribe로 읽으세요. 알림은 묶여서 옵니다. 한 tick 안의 여러 액션이 콜백 한 번으로 합쳐지므로 렌더링에 그대로 쓰기 좋습니다.

미디어 상태는 비어 있는 채로 시작합니다

브라우저가 메타데이터를 확보하기 전까지 duration은 0, canPlay는 false입니다. 트랙 목록이 비어 있는 것도 같은 이유입니다. 이 값들을 읽는 코드는 모두 subscribe를 거쳐야 합니다.

스킨에는 크기가 필요합니다

<video-skin>은 컨테이너를 채우는데, 높이가 없는 컨테이너는 아무것도 아닌 크기로 무너집니다. 크기를 주세요. 

video-skin {
  display: block;
  width: 100%;
  aspect-ratio: 16 / 9;
}

위의 표들은 옮겨 적은 것이 아니라 실행 중인 플레이어에서 읽어낸 것이라, 이 저장소의 빌드를 그대로 설명합니다. 여러분의 빌드는 Object.keys(store)로 확인하세요.
